# pdm-deps-assets Specification

## Purpose

Pdm `DepsAndAssets` packs a committed `pdm.lock` into one offline deps tarball and installs that closure with `pdm sync` from a local file index.

## Requirements

### Requirement: Pdm ecosystem under DepsAndAssets

The program SHALL support `DepsAndAssets` with ecosystem `Pdm`. Policy SHALL carry an optional lock subdirectory relative to the repository root; unset means `pdm.lock` at the root. Apply SHALL dispatch Pdm materialization, the Python slot atom, and `dev-lang/python` runtime lanes for this ecosystem.

#### Scenario: Root lock uses the Pdm path

- **WHEN** policy uses `DepsAndAssets` with ecosystem `Pdm` and no lock subdirectory
- **THEN** planning reads `pdm.lock` at the repository root and uses Python runtime lanes

### Requirement: Missing pdm.lock hard-fails

When `pdm.lock` is absent at the policy path for a `DepsAndAssets Pdm` package, planning SHALL hard-fail that package. The program SHALL NOT create or refresh a lock by running `pdm lock`.

#### Scenario: Absent lock fails planning

- **WHEN** a candidate tag has no `pdm.lock` at the policy path
- **THEN** planning fails for that package and does not write a lock file

### Requirement: Parser accepts pdm.lock documents

The parser SHALL accept a `pdm.lock` that records distribution names, versions, filenames, and file hashes. It SHALL accept a lock that stores no download URL and no per-distribution group membership. A document the parser cannot read SHALL hard-fail the package.

#### Scenario: Filenames and hashes

- **WHEN** a lock entry names a file and a hash and does not name a download URL
- **THEN** the parser accepts that entry

#### Scenario: Unreadable lock

- **WHEN** `pdm.lock` is present and the parser cannot read it
- **THEN** planning fails for that package

### Requirement: Planning does not execute pdm

Planning a `DepsAndAssets Pdm` candidate SHALL read `requires-python` from the lock or, when the lock omits it, from `pyproject.toml`. Planning SHALL NOT execute `pdm`. An unreadable specifier SHALL record no slot for that candidate.

#### Scenario: Outdated does not run pdm

- **WHEN** `outdated` plans a `DepsAndAssets Pdm` package
- **THEN** the check does not execute `pdm`
- **AND** the recorded slot comes from `requires-python` and the Python slot inventory

#### Scenario: Unreadable specifier

- **WHEN** a candidate's `requires-python` is missing or unrecognized
- **THEN** that candidate records no slot and is not selected for a lane

### Requirement: Packing does not refresh the lock

Packing SHALL NOT run `pdm lock` or `pdm export`. A lock that `pdm export` cannot write, or that `pdm` warns is older than the image `pdm`, SHALL still pack when the locked files can be fetched and their hashes match.

#### Scenario: Export is not required

- **WHEN** `pdm export` would fail because the lock has no environment markers
- **THEN** packing does not run `pdm export` and still publishes the deps tarball

#### Scenario: Old lock warning does not relock

- **WHEN** image `pdm` warns that the lock was generated by an older PDM
- **THEN** packing leaves `pdm.lock` unchanged and does not run `pdm lock`

### Requirement: Packed groups are default and dev

The deps tarball SHALL contain the distributions a `pdm sync -G dev` at the chosen slot would install: the default group plus the `dev` group, after markers for that slot. It SHALL omit a distribution that is installed only by selecting the `lint` group or by passing `-d`. Packing SHALL NOT pass `-d`.

#### Scenario: Dev sync set is packed

- **WHEN** `pdm sync -G dev` at the chosen slot installs a distribution and `pdm sync --prod` does not
- **THEN** the deps tarball contains that distribution

#### Scenario: Lint-only distribution is omitted

- **WHEN** a distribution is installed by `pdm sync -d` and is not installed by `pdm sync -G dev`
- **THEN** the deps tarball does not contain that distribution

### Requirement: One artifact per locked distribution

For each packed locked distribution, the tarball SHALL contain one file: a `py3-none-any` or `py2.py3-none-any` wheel when the lock lists one, otherwise the sdist. It SHALL NOT also contain another file for that distribution. A platform wheel SHALL NOT be chosen in place of the sdist when no pure wheel is listed.

#### Scenario: Pure wheel is the only file

- **WHEN** the lock lists a `py3-none-any` wheel and an sdist for a packed distribution
- **THEN** the tarball contains that wheel and does not contain that sdist

#### Scenario: Sdist when no pure wheel exists

- **WHEN** the lock lists no `py3-none-any` or `py2.py3-none-any` wheel for a packed distribution
- **THEN** the tarball contains that distribution's sdist and does not contain its platform wheels

### Requirement: Build backends for packed sdists and the project

The tarball SHALL contain one artifact, chosen by the same pure-wheel-or-sdist rule, for each direct `build-system.requires` entry of a packed sdist and for the project `build-system.requires` entry `pdm-backend`. A wheel chosen for that entry SHALL stop the walk. The ebuild SHALL leave build isolation on and SHALL NOT depend on those backends as Gentoo packages.

#### Scenario: Project backend is packed

- **WHEN** the project `build-system.requires` names `pdm-backend`
- **THEN** the deps tarball contains a `pdm-backend` artifact
- **AND** the ebuild does not depend on `dev-python/pdm-backend`

#### Scenario: Sdist backend is packed

- **WHEN** a packed sdist declares `build-system.requires` of `setuptools`
- **THEN** the deps tarball contains a `setuptools` artifact
- **AND** the install does not disable build isolation

### Requirement: Locked file hashes are verified

Each packed file that the lock names SHALL match a hash the lock records for that file. A download that does not match SHALL hard-fail packing. The program SHALL NOT publish that tarball.

#### Scenario: Hash mismatch

- **WHEN** a fetched file named by the lock does not match the lock hash
- **THEN** packing fails and no deps tarball is published

### Requirement: Non-Linux-only distributions are omitted

The packer SHALL omit a distribution whose incoming edges are all Windows or macOS platform markers. It SHALL keep a distribution that also has an unconditional or Linux edge.

#### Scenario: Windows-only distribution omitted

- **WHEN** a distribution is required only by a Windows platform marker
- **THEN** the deps tarball does not contain that distribution

### Requirement: Pdm distfile name

For package name PN and version PV without revision, the program SHALL name the Pdm distfile `{pn}-{pv}-deps.tar.xz` and the assets release `{pn}-{pv}`. Names SHALL use the overlay package name.

#### Scenario: cmake-language-server deps name

- **WHEN** publishing assets for package `cmake-language-server` at PV `0.1.10`
- **THEN** the distfile basename is `cmake-language-server-0.1.10-deps.tar.xz` and the release tag is `cmake-language-server-0.1.10`

### Requirement: Source archive records the real tag

When rewriting a Pdm ebuild, the upstream source archive URL SHALL use `archive/refs/tags/<tag>.tar.gz`, where `<tag>` is the git tag that parsed to that PV. The assets deps URL SHALL stay parameterized with `${PV}`. The program SHALL NOT replace `<tag>` with a spelling that is not that tag.

#### Scenario: Prefixed tag

- **WHEN** the tag that parsed to PV `0.1.11` is `v0.1.11`
- **THEN** the archive URL contains `refs/tags/v0.1.11.tar.gz`
- **AND** the assets deps URL contains `${PV}`

### Requirement: Rewrite sets the Python slot atom

When rewriting a Pdm ebuild, the program SHALL set the Python dependency to `dev-lang/python:<slot>` and `PYTHON_COMPAT` to that slot alone, where `<slot>` is the slot runtime-lanes chose for that PV. The program SHALL rewrite each `/usr/bin/python<major>.<minor>` interpreter path to `/usr/bin/python<slot>`. Donor `IUSE`, `src_test`, and the remainder of `src_install` SHALL be preserved.

#### Scenario: Slot atom follows the chosen slot

- **WHEN** apply writes a Pdm PV whose chosen slot is `3.13` and the donor names `/usr/bin/python3.12`
- **THEN** the ebuild depends on `dev-lang/python:3.13`
- **AND** `PYTHON_COMPAT` names `python3_13` only
- **AND** the venv interpreter path is `/usr/bin/python3.13`
- **AND** donor `IUSE` and `src_test` remain

### Requirement: Offline sync from the packed files

The published deps tarball SHALL be sufficient for `pdm sync --prod` and `pdm sync -G dev` to install from a local `find_links` directory with no network access. That install SHALL NOT fetch distribution files from a package index.

#### Scenario: Emerge does not fetch distributions

- **WHEN** the ebuild installs a Pdm package from the deps tarball
- **THEN** the install does not contact a package index for those distributions
